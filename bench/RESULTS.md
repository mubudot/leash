# Receipt gas comparison

Generated by `python3 bench/gas.py` from the fixed matrix in `gas.py`. All 18 scenarios and all three repetitions are included; repetitions must agree exactly. The JSON contains every sample, calldata, logs, state, hashes and compiler versions.

Measured on Linux aarch64, Fe 26.5.1 (149c758), Anvil/Cast 1.8.7 (985eeea031d79922cd654d4e94e6c3701e1c7d73), solc 0.8.30+commit.73712a01; Node v22.23.3.

Fe uses Sonatina O2. Both Solidity builds use Osaka and optimizer runs 200. Legacy and via-IR are separate columns throughout. Each sample starts a fresh Anvil at timestamp 1793664000, chain 31337, Osaka, with one-second block increments. See [method and reproduction](README.md) and [storage layout](LAYOUT.md).

This is a bare-uint-versus-typed ergonomics/default-code comparison. It measures these implementations and pinned builds; it establishes no general language gas ranking.

## Intrinsic, floor and refund accounting

Each cell below is **standard intrinsic / calldata floor / charged above intrinsic / capped refund / floor top-up**. These are gas units computed from that sample's actual input bytes and opcode trace. Charged above intrinsic is receipt gas minus standard intrinsic; it includes any floor charge and is not an execution-only metric.

For `Z` zero and `N` nonzero input bytes, tokens = `Z + 4N`. Standard intrinsic is `21000 + 4*tokens`, plus `32000 + 2*ceil(input_bytes/32)` for creation. The floor is `21000 + 10*tokens`. The reported receipt is checked against `max(gross - min(refund_counter, gross//5), floor)`. Gross comes from the top-level trace gas balance, plus code deposit for creation. Resetting an already-spent agent clears its spent word and earns a refund; the transient mutex earns none. Sources: [EIP-7623](https://eips.ethereum.org/EIPS/eip-7623), [EIP-3860](https://eips.ethereum.org/EIPS/eip-3860), [EIP-3529](https://eips.ethereum.org/EIPS/eip-3529).
